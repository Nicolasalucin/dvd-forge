# Kinodisc 1.1 walkthrough (2026-11-17)

Real app (walkthrough build, CDP), personas: newcomer making a holiday DVD with
phone videos, and an advanced user with interlaced camcorder footage, long
names and the CLI. Test media: vertical 1080×1920 phone clip, 1080i MPEG-2
(top field first), a 1280×720 clip with an emoji and a 70-character name,
and a 60 s clip with four hard scene cuts.

## Findings

| # | Severity | Finding | Status |
|---|---|---|---|
| 1 | Blocker | A project created in the app could not be produced: the empty starting background (`background.png`, no file) was read as an image ("No se pudo cargar «background.png»"). Every new project failed in 1.0.0. | Fixed: `MediaAsset::is_placeholder`, composed on the menu colour; never packaged. |
| 2 | Blocker | Every interlaced source failed to encode: FFmpeg 9 (the version Kinodisc downloads) removed `-top`. DVD, AVCHD/BD episodes and HD menus. | Fixed: field order through `setfield=tff/bff` (all FFmpeg versions); test. |
| 3 | Major | Templates wrote their own name ("Retro CRT") as the menu title, burned onto the disc. | Fixed: project name, or the title the user typed; regression test. |
| 4 | Major | DVD encoding was slow: a 1:50 project took 365 s. Pass 1 combined `b_strategy 2` with full RD comparison (44 s of 52 s); `qmin 1` spent 78 % more bits where quality is already transparent. | Fixed: light statistics pass, cheap quality flags only. 365 s → 66 s, same PSNR. |
| 5 | Major | `cargo test` wrote 36 fake entries into the developer's real "Recent projects". | Fixed: tests use a throw-away data folder. |
| 6 | Major | Opening a recent project whose file is gone showed a raw OS error twice and kept the entry. | Fixed: entries marked "Not found" with a remove button; localized `E_PROJECT_NOT_FOUND`. |
| 7 | Major | Vertical (phone) videos were shown cropped and stretched in the trimmer, strip and thumbnails, while the disc shows them with side bars. | Fixed: TV-shaped player frame, `object-contain` previews. |
| 8 | Major | Discs rendered with the CLI have menus without labels, thumbnails or text: composition only happens in the app. | Fixed: `kinodisc-render::compose` draws the same layers (layout, styles, items, system fonts with emoji/symbol fallback). |
| 11 | Major | The menu cache key ignored the composed artwork: a changed thumbnail or font could reuse the previous menu. | Fixed: the composition's hash is part of the key. |
| 12 | Major | The bitrate plan disappeared after applying a template, undo, a priority or disc-setting change (cleared without recalculating): empty space meter. | Fixed: recalculated whenever it is missing. |
| 13 | Major | Production dialog: a long output path widened the left column, cutting the right one and adding a horizontal scrollbar. | Fixed: `minmax(0,1fr)` column. |
| 14 | Minor | Preview panel showed developer jargon: "navigation graph computed by Rust", "D-Pad route fingerprint" hash, "nodes · edges", "Refresh graph". | Fixed: plain wording, hash and counts removed. |
| 15 | Minor | "Fuente" means both *font* and *source*: English showed "Source" for the font picker and "Font size" for the size of the files. | Fixed: "Tipo de letra" / "Tamaño de los archivos". |
| 16 | Minor | "← Menu" over a playing video was hard to read. | Fixed: dark pill. |
| 17 | Minor | With fewer episodes than template cells (one disc per episode, last page) the cards sat in the top-left corner. | Fixed: used rows and each row centred; test over every template. |
| 9 | Minor | Episode thumbnail panel showed an internal hash file name and "Quitar ruta" (jargon). | Fixed: "Restablecer". |
| 10 | Minor | Localized backend errors appended the Spanish original in other languages. | Fixed when the original is a known sentence. |
