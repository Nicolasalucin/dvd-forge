# Security review — Kinodisc 1.0 (anti-springboard)

Skill: `.claude/skills/desktop-hardening`. Threat model: an attacker controls
some input (project, bundle, media, subtitle, a writable folder, a web page)
and wants Kinodisc — a trusted program that launches other programs — to run
code, plant files or read data for them.

| Area | Finding | Status |
|---|---|---|
| Tool discovery | `cwd/resources/toolchains/<os>` was searched for FFmpeg/DVDAuthor: opening Kinodisc from a download folder could run a planted `ffmpeg.exe`. | **Fixed** — removed; test `current_directory_is_never_searched_for_tools`. |
| Downloaded tools | Only the archive hash was checked at install time; files could be swapped afterwards. | **Fixed** — per-file SHA-256 recorded in the provenance file and verified (once per process) before a tool in the per-user folder is used; unrecorded or changed files are refused. Pre-1.0 installs without per-file hashes are re-downloaded. Test `tampered_or_unknown_files_in_the_toolchain_are_refused`. |
| DLL planting | Windows loads DLLs from a program's folder first. | **Fixed** — an unrecorded `.dll/.so/.dylib` in the per-user tool folder makes the folder untrusted (same test). |
| Helper programs | The provisioner ran `curl`/`tar` by bare name. | **Fixed** — absolute `%SystemRoot%\System32` paths on Windows. |
| Tool folder permissions | — | **Fixed (Unix)** — created `0700`. Windows: `%LOCALAPPDATA%` is per-user by default. |
| Process arguments | All tools are spawned with argument vectors, never a shell; inputs are absolute paths behind `-i` with the FFmpeg protocol whitelist. | OK |
| IPC: image reads | `read_image_data_url` accepted any file path. | **Fixed** — image extensions only (+ existing 32 MB cap). |
| IPC: open folder | Could hand a non-folder to the system opener. | **Fixed** — folders only. |
| Local media server | 127.0.0.1, random per-file tokens, media types only. | OK |
| WebView | Strict CSP, asset protocol off, no DevTools in release; the walkthrough DevTools port exists only in the debug config. | OK |
| Bundles / parsers | Manifest-first, traversal-safe import with rollback; seeded robustness tests for verifier, HDMV, subtitles and bundles. | OK |
| CI supply chain | Actions pinned by moving tags; all jobs had `contents: write`. | **Fixed** — every action pinned to a commit SHA; read-only by default, write only for the publish job. |
| Release integrity | No checksums. | **Fixed** — `SHA256SUMS.txt` published with every release. |
| Code signing | Binaries are unsigned (SmartScreen/Gatekeeper warnings; no publisher identity). | **Risk accepted for now** — needs the owner's account (e.g. SignPath Foundation for open source, or a certificate). |
| Dependencies | Two unused dependencies. | **Fixed** — removed `unicode-segmentation`; `libc` is Unix-only. |
